## Future evidence update rules

Record date, source revision, run command, seed, OS/runtime/browser/PostgreSQL versions, database durability settings, test isolation, variant, actual versus simulated layer, observed IDs/revisions and retained artifact path. A browser screenshot alone is insufficient for atomic record/receipt assertions. A SQL dump alone is insufficient for browser process restart. The [failure matrix](INVARIANTS_AND_FAILURE_MATRIX.md) specifies both sides of each recovery.

Only add Markdown links after the target executable/artifact actually exists. For future README claims, link the corresponding C-row's real test and/or reproducible demo, state assumptions, and preserve limitations. Phase 0 does not certify any reliability target as satisfied.
